# README 图片

根 `README.md` 引用的图片放这里。**必须提交进仓库**，所以不能放 `.gitignore` 掉的
`screenshots/`，也不能放 `static/`——那个目录会被 `--include-data-dir` 打进发布产物
（`packaging/build.py:127`），README 的图白占每个安装包的体积。

## 目前用到的

| 文件 | 内容 | 说明 |
|---|---|---|
| `logo.png` | 标题上方的应用图标 | 由 `static/logo.ico` 转出（Qt 读 ICO 存 PNG），256×256、**透明背景**。改名或删了要同步改 README |
| `home.png` | 主页 | 真实窗口截图，浅色主题，1375×950。README 里用 `width="900"` 显示 |

## 截图约定

1. **路径一律打码。** 主页上会显示三个绝对路径（hero 卡的「下载目录」、下载卡的「下载到」、
   关于卡的「配置目录」），默认值里带着 Windows 用户名。三处都要盖掉——**很容易只盖前两个**
   （hero 和关于卡显眼，下载卡那行字号更小）。
2. **版本号要跟 `pyproject.toml` 一致。** 主页两处显示 `APP_VERSION`：hero 卡和关于卡。
   发版前截的图到发版后就成旧号了，从源码跑（`uv run python main.py`）才是当前版本，
   **别用 `dist/` 里的旧安装包截**。
3. **别用 `scripts/screenshot_pages.py` 的离屏输出。** 那些脚本里假数据的封面 URL 是
   `x.invalid`，渲出来的**封面全是空白占位**，放进 README 很难看（主页那张例外，它用的是
   `static/showcase/` 里的真实素材——但既然要真机截，就统一真机截）。
4. 窗口标题栏留着，那让它看起来是个真应用。宽度 1500px 以内即可，README 里用 `width` 属性
   控制显示大小，**不要写百分比**（GitHub 的 `img` 宽度基本只认整数）。
5. 深浅两套只提交浅色：README 在 GitHub 亮暗主题下用的是同一张图，深色图配浅色页面边框很突兀。

## 为什么截图只放主页

**版权**。表情包详情、收藏集、下载队列这几页截出来必然带满 B 站的表情图和收藏集封面，
那是 B 站与各位创作者的作品，不是本项目的产物。

主页截图里同样有 B 站素材（`static/showcase/` 那批，应用欢迎页本来就在用），所以严格说
它也不是「版权干净」的一张——这是本项目的取舍：**只展示应用自身界面最集中的那一页**，
不再额外公开一批受版权保护的图。这是个判断，不是法律结论；有疑问请自行评估。

**别顺手把另外几张补上。** 想加界面截图之前先想清楚图里的内容归谁。
